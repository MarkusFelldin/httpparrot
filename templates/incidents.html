The Cascading 503

Microservices

A single failing health check brought down an entire microservices cluster through cascading 503 responses.

200 All services healthy. Load balancer distributing traffic normally.
503 Auth service deploys bad config. Health check starts failing.
502 Gateway can't reach auth service. All authenticated requests fail.
503 Dependent services start failing. Circuit breakers trip.
200 Config rolled back. Services recover within 5 minutes.
Lesson: Always implement circuit breakers and don't let one service's failure cascade. Return 503 with Retry-After header.

The Rate Limit Surprise

API Design

A mobile app update caused 10x traffic spike. The API returned 429s, but the app retried immediately — making it worse.

200 Normal traffic: 1000 req/min. API handles it fine.
429 App update causes 10,000 req/min. Rate limiter kicks in.
429 App retries immediately without backoff. Traffic doubles to 20,000 req/min.
503 Rate limiter overwhelmed. Entire API goes down for all users.
200 Hotfix deployed: app respects Retry-After header. Traffic normalizes.
Lesson: Always include Retry-After with 429. Client apps must implement exponential backoff.

The Silent 200 Error

Anti-Pattern

An API returned 200 OK for every request — even errors. Monitoring showed 100% success while users couldn't log in.

200 API returns 200 with {"error": "invalid_credentials"} in body.
200 Monitoring shows 100% success rate. No alerts triggered.
200 Users report login failures. Support tickets pile up for 6 hours.
401 Fix: Return proper 401 for auth failures. Monitoring catches it instantly.
Lesson: Never return 200 for error conditions. Proper status codes enable monitoring, caching, and client error handling.

The Redirect Loop

Redirects

A misconfigured nginx rule created a 301 loop between HTTP and HTTPS, crashing browsers and blocking search engines.

301 http://site.com → https://site.com (correct HTTPS upgrade)
301 https://site.com → http://site.com (bad rule redirects back!)
301 Infinite loop. Browsers show ERR_TOO_MANY_REDIRECTS.
200 Fix: Remove conflicting rule. Test with curl -L to verify chain.
Lesson: Always test redirect chains with curl -L. Use 308 for HTTPS upgrades to preserve POST requests.
