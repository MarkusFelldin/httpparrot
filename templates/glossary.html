HTTP Glossary

Quick reference for HTTP terminology

Idempotent

A request method is idempotent if multiple identical requests have the same effect as a single request. GET, PUT, DELETE, HEAD, OPTIONS are idempotent. POST and PATCH are not.

Safe Method

A method is safe if it doesn't modify server state. GET, HEAD, OPTIONS are safe. Safe methods can be cached and prefetched.

Content Negotiation

The mechanism by which client and server agree on the response format via Accept, Accept-Language, and Accept-Encoding headers.

ETag

An opaque validator for a resource version. Used with If-None-Match for conditional requests and cache validation (304 Not Modified).

CORS

Cross-Origin Resource Sharing. A mechanism using HTTP headers to allow a server to indicate which origins can access its resources.

Preflight Request

An OPTIONS request sent automatically by browsers before certain cross-origin requests to check if the actual request is safe to send.

TTFB (Time to First Byte)

The time between sending a request and receiving the first byte of the response. Key performance metric indicating server processing time.

HSTS

HTTP Strict Transport Security. A header that tells browsers to only connect via HTTPS, preventing protocol downgrade attacks.

CSP (Content Security Policy)

A security header controlling which resources the browser can load, mitigating XSS and injection attacks.

Cache-Control

Header directing caching behavior: max-age sets freshness, no-cache requires revalidation, no-store prevents caching entirely.

Vary

Response header telling caches which request headers affect the response. Vary: Accept means JSON and HTML responses are cached separately.

Transfer-Encoding

How the message body is encoded for transfer. chunked means the body is sent in pieces, enabling streaming without knowing total size upfront.

Keep-Alive

HTTP/1.1 default: reuse TCP connections for multiple requests, avoiding the overhead of establishing new connections each time.

REST

Representational State Transfer. An architectural style using standard HTTP methods on resource URLs. Coined by Roy Fielding in 2000.

Status Code

A 3-digit number in HTTP responses indicating the result: 1xx informational, 2xx success, 3xx redirection, 4xx client error, 5xx server error.
